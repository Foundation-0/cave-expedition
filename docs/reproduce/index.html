00//Standalone check

No extra files

One clone. Three commands.

Clone this repo and run the AUDIT-002 checker. It uses the Python standard library only. Run it in all three modes. The three runs must agree. Mode two strips bare asserts, so a checker that leans on them fails there. Mode three turns warnings into errors.

git clone https://github.com/Foundation-0/cave-expedition
cd cave-expedition
python3 -I -B verification/checks/check_003_seam01_ropt.py
python3 -I -O -B verification/checks/check_003_seam01_ropt.py
python3 -I -B -W error verification/checks/check_003_seam01_ropt.py

What it proves: the rank chain and its sharpness in AUDIT-002, decided in exact Gaussian rational arithmetic and cross-checked by a second route with no shared code. What it does not prove: newness. Newness needs the prior-art read in the log and the outside ruling beside it.

02//Folder layout

Two settings

Point the suite at one root.

EXPEDITION_ROOT names the folder that holds the sibling work. If you leave it unset, scripts fall back to this repo root and cross-repo checks will miss their inputs. GEMINI_SESSIONS_DIR names the private transcript folder for check_001 and check_002 only. That folder is not in this repo and not public. Expect those two scripts to stop with a missing-path error on a bare clone. That stop is the honest outcome, not a failure of the ledger.

export EXPEDITION_ROOT=/path/to/expedition
python3 -I -B verification/checks/check_010_spectral_inertia_reaudit.py
python3 -I -O -B verification/checks/check_010_spectral_inertia_reaudit.py
python3 -I -B -W error verification/checks/check_010_spectral_inertia_reaudit.py

Swap in any script name from the table. Keep the three modes for every run. Record the exact command, the commit you ran at and the full output. A pass with no recorded command does not count as a replay.

03//Honesty notes

Read before you compare runs

Three traps for a careful reader.

  1. Early checks pin early code. check_007 covers AUDIT-011, 012 and 013 as first audited. check_008 covers AUDIT-014, 015 and 016 as first audited. The patched verdicts live in the re-audit scripts: check_011 for gravity, check_010 for spectral, check_012 for continuum. Run the re-audit script for the current standing of any R row. Running only the early script replays the first pass, defects included.
  2. Upstream files move. Cross-repo checks import live sibling code. If a sibling draft changed after the audit date, a fresh run tests new bytes against old expectations. Pin each sibling to the commit named in the log row before you compare outputs. A drift failure tells you the pin slipped. It does not by itself refute the audit. Most rows name no commit or hash: 15 of the 22 record no byte pin. verification/expedition_root.pins.json lists the values the rows do record and which file each hash covers, and verification/check_expedition_root.py hashes those files in your folder the way the check scripts do and compares the results with them.
  3. Two scripts need private inputs. check_001 and check_002 read raw session transcripts through GEMINI_SESSIONS_DIR. Those transcripts stay out of this repo by design. Their findings still stand in the log with script names and hashes, but a public reader cannot replay them end to end today.

04//Read a verdict

Four words, three oracles

What each word lets you conclude.

WordMeaningSafe next step
VERIFIEDPassed each gate that applies, with clean replay and no counterexample found. True inside the stated scope only.Build on it inside that scope. Cite scope with the result.
PARTIAL / FRAGILECore effect runs, but a robustness, scope or gate test fails.Patch or narrow the claim, then seek a re-audit. Do not build on the wide form.
FALSIFIEDA concrete counterexample, a null hit, or a fatal gate failure refutes the claim as stated.Retract or rebuild. The row stays as the record of why.
NOT_SHOWNTested inputs passed with no counterexample, but coverage stops short of the full claim.Report how much ran, in plain counts. Never report it as a pass.

Pair every verdict with its oracle. Exact means the checker decides the claim for all inputs in scope. Sampled means the checker saw finite inputs only, even when each sum ran in exact arithmetic. Anchor means held-out data tests the spec itself, so no tuning against it is allowed. Pair both with the novelty tag: N0 known, N1 local advance, N2 new ground. Truth and newness are separate calls. A row can be true and still be N0.
